# 01 · SPEC — «Ассистент»: поиск и разбор информации по звонкам

Два уровня одной функции:
1. **Раздел «Ассистент»** — оперирует всеми звонками; каждый диалог = новый чат.
2. **Ассистент внутри звонка** (вкладка в карточке звонка) — отдельный постоянный чат
   именно этого звонка; отвечает по его расшифровке, может привлекать другие звонки.

## 1. Ограничение области (жёсткое)
Контекстное окно модели — **8K токенов** → под капотом строго RAG. Ассистент ТОЛЬКО
ищет и разбирает информацию из звонков (расшифровки + рекапы). Он **не** пишет письма,
не генерирует произвольные тексты, не выполняет команды.

Пайплайн запроса:
1. **Классификация.** Запрос на генерацию (маркеры: «напиши, составь, сгенерируй,
   придумай, переведи, отправь, создай, запланируй, оформи») → отказ БЕЗ поиска:
   заголовок-нота «Вне области ассистента» (иконка shield) + текст: область — поиск и
   разбор; предложить собрать факты (решения, задачи, сроки). Блок «Контекст поиска»
   у отказа не показывается (поиска не было).
2. **Retrieval.** Поиск по индексу; в контекст — top-k фрагментов до бюджета
   ~5.5K токенов (остальное окно: системная инструкция ~0.6K + вопрос + запас на ответ).
3. **Ответ строго по фрагментам** + источники (call_id + таймкод). Никаких фактов вне
   выданных фрагментов.
4. **Пусто** → честное «не найдено»: глобально — «По звонкам ничего не найдено.
   Уточните имя участника, тему или период»; в звонке — «В этом звонке этого не
   нашлось» + чип-эскалация **«Искать во всех звонках»** (создаёт новый глобальный чат
   с тем же запросом и переводит в раздел).

## 2. Индекс
- Только звонки со статусом `ready`. `processing` и `error` не индексируются.
- Шапка раздела: чип «в поиске X из Y звонков · ЧЧ ч ММ мин»; tooltip: «Записи в
  обработке и с ошибкой не участвуют в поиске».

## 3. Чаты
Глобальный раздел:
- Левая колонка 232px: кнопка «Новый чат», список с группировкой по дню
  (Сегодня/Вчера/…), активный чат подсвечен, удаление — trash по hover
  (строка списка — `div role="button"`, НЕ вложенные `<button>`).
- Новый чат создаётся первым отправленным вопросом; заголовок = вопрос, усечённый
  до ~42 симв.
- Пустое состояние: заголовок «Поиск по всем звонкам», подпись «Вопрос — это поиск по
  расшифровкам и рекапам, ответ — с указанием источников. Каждый диалог — новый чат»
  + 4 чипа-подсказки.

Внутри звонка:
- Вкладка «Ассистент» (иконка `chat`) доступна только при `ready`.
- Один тред на звонок, персистится (в моке — in-memory store по call_id; в проде — БД).
- Подпись пустого состояния: «Чат этого звонка. Ответы строятся по его расшифровке;
  если факт найден в другом звонке — источник будет указан».

## 4. Сообщение-ответ (AnswerMsg)
- Текст (может быть многострочным, `white-space: pre-line`).
- **Источники** — чипы: свой звонок → `clock` + таймкод, клик = переключить на
  транскрипт и перемотать плеер; другой звонок → `doc` + «Название · таймкод»,
  клик = открыть звонок.
- **«Контекст поиска»** — свёрнутый `details`: цитаты-фрагменты (имя спикера в его
  цвете + звонок + таймкод + текст, рамка слева) и mono-строка
  «фрагментов: N · ≈X.XK токенов · окно 8K».
- **Действия** (по hover облака, только у kind=answer): «Скопировать» (галочка 1.4s),
  «Поделиться» — дропдаун: «Скопировать с источниками» (текст + `\n\nИсточники: `
  список «Название · т/к» через `;`), «Отправить в почту…».
- Ожидание: пузырь «Поиск по N звонкам…» / «Поиск…» с волной (нейтральный
  `--text-3`), задержка ответа в моке 800–900 мс.

## 5. ⌘K «Найти или спросить»
- Поле в сайдбаре: иконка `sparkle`, текст «Найти или спросить», `⌘K`, класс
  `ai-field ai-field--panel`. Текст не переносится (nowrap + ellipsis).
- Плейсхолдер палитры: «Найти звонок или спросить ассистента…».
- Команда «Ассистент — поиск по звонкам» в списке команд.
- **Fallback**: если по запросу нет ни команд, ни звонков — секция
  «Ничего не найдено · Ассистент» с пунктом «Спросить ассистента» (подстрока:
  «„запрос“ — поиск по N звонкам»), выбирается стрелками, срабатывает по Enter →
  новый глобальный чат с этим запросом.

## 6. Брендинг (не нарушать)
- Графит-моно: НЕ перекрашивать логотип, кнопки, навигацию. Красный — только
  запись/деструктив. Цвет спикеров (`--sp1…5`) — только для голосов/аватаров.
- Единственный цветной бренд-элемент ассистента — **`ai-field`**: анимированное
  conic-градиентное кольцо 1px из палитры голосов БЕЗ тёплых тонов:
  `sp1 → sp5 → sp2 → sp4 → sp1`, оборот 7s linear, по hover 2.8s; реализация:
  `border: transparent` + два background-слоя (padding-box заливка `--ai-bg`,
  border-box conic от `@property --ai-a`). Применяется ровно к трём полям: сайдбар
  «Найти или спросить», контейнер ⌘K-палитры, композер вопроса (раздел + звонок).
- Лёгкий `fade-up` на появление сообщений. Больше никакой анимации/цвета.

## 7. Тексты (деловой регистр)
Все строки — как в моке (`wk2-assistant.jsx`, `wk2-screens.jsx`, `wk2-app.jsx`).
Без разговорности, без глаголов 1-го лица процесса. Тех-детали (токены, окно) —
только в mono-строке «Контекста поиска».

## 8. Acceptance checklist
- [ ] Раздел «Ассистент» в навигации (иконка `chat`) + мини-рейле + ⌘K.
- [ ] Индекс: только ready; чип статистики с корректной суммой длительностей.
- [ ] Новый чат на каждый диалог; список чатов: группировка, удаление, активность.
- [ ] Классификация: генеративный запрос → отказ без retrieval.
- [ ] Ответ: источники-чипы с переходами (seek / открыть звонок).
- [ ] «Контекст поиска»: фрагменты + счётчик токенов; у отказа отсутствует.
- [ ] «Не найдено» честное; в звонке — эскалация «Искать во всех звонках».
- [ ] Тред звонка персистится и не смешивается между звонками.
- [ ] Copy / «Скопировать с источниками» работают (clipboard rejection ловится).
- [ ] ⌘K fallback «Спросить ассистента» с Enter.
- [ ] `ai-field` анимируется, темы light/dark, ничего больше не перекрашено.
- [ ] Консоль чистая: без вложенных `<button>`, без unhandled rejections.
