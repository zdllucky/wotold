# TD-21(e) — эмпирика потери аудио-устройства (2026-07-27)

Машина разработчика, macOS, Swift 6.3.3. Переключение дефолтного входа между
`D pods max` (AirPods Max, Bluetooth) и `Микрофон MacBook Pro` во время записи.

## 1. Утверждение аудита подтверждено

Смена устройства **молча** останавливает подачу кадров: ошибки нет, исключения
нет, счётчик просто перестаёт расти.

```
t=2.0s кадров=45056 (+12288)  running=да
>>> ПЕРЕКЛЮЧИЛИ вход
t=3.0s кадров=65536 (+16384)  running=НЕТ
t=3.5s кадров=65536 (+0)      running=НЕТ
...
t=25.0s кадров=65536 (+0)     running=НЕТ     ← 23 секунды тишины
```

Дорожка **не оживает сама** — проверено на 25-секундном хвосте.

## 2. `isRunning` и уведомление как признаки живости не годятся

- `AVAudioEngineConfigurationChange` приходит, но с разной задержкой:
  **~0.5 с** при переключении на встроенный микрофон и **~3.5 с** при возврате
  на Bluetooth.
- Всё это время `engine.isRunning` возвращает `true` при нуле кадров.
- Уведомления приходят пачками — замечено три подряд за секунду.
- Одно уведомление приходит сразу при старте, до всякой смены устройства.

Вывод: решение «сообщать пользователю» принимает watchdog по факту
прекращения кадров, а уведомление годится только как быстрый триггер.

## 3. Восстановление: работает ровно один способ из трёх

| способ | результат |
|---|---|
| `removeTap` + `installTap` на существующем engine | **падение** — ObjC-исключение из `AVAudioEngineGraph::InstallTapOnNode`, из Swift не ловится, процесс умирает |
| `engine.start()` без переустановки tap'а | `-10868` `FormatNotSupported` — формат tap'а прибит на момент установки |
| **новый `AVAudioEngine` целиком** | **работает**, кадры идут через ~0.5 с |

Частота железа при этом реально меняется: замерено **24000 → 48000 Гц**.
Поэтому `AVAudioConverter` обязателен к пересозданию — он тоже прибит к
формату входа на момент создания.

## 4. Сквозная проверка на собранном сайдкаре

Запись 22 с, переключение на 5-й секунде на медленный (Bluetooth) путь:

```json
{"event":"device_lost","leg":"mic","message":"микрофонная дорожка молчит 4.7 с — устройство ввода пропало или сменилось"}
{"event":"device_recovered","leg":"mic","gap_sec":4.83,"restarted":true}
{"event":"stopped","duration_sec":22.03,"mic_bytes":536408}
```

536408 байт = **16.8 с аудио из 22 с**. До фикса дорожка была бы мертва с
5-й секунды до конца — то есть ~5 с из 22.

На быстром пути (переключение на встроенный микрофон) провал укладывается в
0.8–1.4 с и порог в 3 с намеренно молчит: сообщать о каждом мелком
переключении значило бы шуметь.

## Ограничения

- Один Mac, одна пара Bluetooth-наушников, два реальных устройства ввода.
- Не проверено: выдёргивание USB-интерфейса, смена частоты устройства другим
  приложением, полное исчезновение всех входов.
- Системная дорожка (Core Audio Process Tap) этим механизмом **не** покрыта:
  у неё нет `AVAudioEngine`. Эквивалент — слушатель свойств Core Audio,
  вынесен отдельной задачей.
