# Релизы и подпись обновлений

> Мейнтейнерский документ. Пользователю ничего из этого делать не нужно —
> ему достаточно [страницы установки](https://zdllucky.github.io/wotold/download/).
> Ключевые действия здесь требуют доступа к секретам репозитория и выполняются
> владельцем.
>
> Контекст: M11 и раздел 16 [паспорта](ПАСПОРТ_ПРОЕКТА.md), S1 (изоляция
> секретов между джобами CI).

## Подпись обновлений (M11)

Tauri-ключ minisign генерируется **один раз** за всё время жизни продукта:

```bash
pnpm --filter @wotold/desktop exec tauri signer generate -w ~/wotold-tauri-signing.key
```

Результат:

1. **Публичный ключ** → в `apps/desktop/src-tauri/tauri.conf.json` → `plugins.updater.pubkey`. Коммитится в репозиторий.
2. **Приватный ключ** + пароль → в GitHub-секреты репозитория:
   - `TAURI_SIGNING_PRIVATE_KEY` — содержимое файла
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — пароль с генерации
3. **Офлайн-бэкап** приватного ключа — зашифрованный архив на внешнем носителе.

> ⚠️ **Потеря приватного ключа = невозможность доставлять обновления существующим
> установкам.** Новый ключ потребует переустановки всех клиентов. См. M11.9 паспорта.

По S1 эти два секрета доступны **только** джобе сборки приложения
(`.github/workflows/release-app.yml`) и не должны быть достижимы ни с одного
PR-триггера. На публичном репозитории это критично: PR из форка не имеет права
получить подписывающий ключ.

## Как выпускается релиз

Merge в `main` релиза **не делает**. Выпуск — отдельное решение: Actions → **Release** →
Run workflow.

| Вход | Что делает |
|---|---|
| `bump` | `patch` / `minor` / `major` — от текущей версии |
| `version` | Точная `X.Y.Z`, побеждает `bump`. Нужна для первого выпуска (`1.0.0`) |
| `mandatory` | Обновление поставится у пользователей само, без спроса |
| `dry_run` | Посчитать версию и остановиться, ничего не публикуя |

Workflow проставляет версию во все четыре файла, сверяет их, отказывается переиздавать
существующий тег, коммитит, тегает и запускает сборку.

Сборка (`release-app.yml`) вызывается **напрямую**, а не через push тега: тег, запушенный с
`GITHUB_TOKEN`, по правилам GitHub не запускает workflow, и цепочка обрывалась бы на созданном,
но не собранном теге. Ручной `git tag vX.Y.Z && git push --tags` продолжает работать — у сборки
остался собственный триггер.

### Когда ставить `mandatory`

Мажорная версия обязательна и без галки — она нужна, чтобы форсировать `minor` или `patch`.
Единственный реальный повод — критический фикс безопасности: по semver он приезжает патчем, а
патчи по умолчанию только предлагаются.

Признак едет в теле аннотированного тега и оттуда попадает первой строкой в release notes
(`!mandatory`). Обходной путь появился потому, что `latest.json` целиком генерирует
`tauri-action` — своих полей в манифест не добавить, и notes оказались единственным полем,
которое доезжает до клиента. Читает его `updater::classify`.

Обязательное обновление **никогда не прерывает запись или обработку**: оно ждёт простоя
сколько потребуется (`updater::install_when_idle`).

## Homebrew

Каск живёт в отдельном репозитории [zdllucky/homebrew-wotold](https://github.com/zdllucky/homebrew-wotold),
шаблон — [`.github/homebrew/wotold.rb.tmpl`](../.github/homebrew/wotold.rb.tmpl). Релизный
workflow подставляет версию и SHA256 и коммитит результат.

Шаблон лежит в основном репозитории намеренно: правка упаковки едет тем же PR, что и правка
приложения. Расхождение между собранным и описанным в каске обнаруживается иначе только
сломанной установкой у пользователя.

Шаг требует секрета `HOMEBREW_TAP_TOKEN` (fine-grained PAT с доступом только к тапу) — без него
он молча пропускается, и релиз всё равно проходит.

## Версионирование

Версия обязана совпадать в четырёх местах — `apps/desktop/src-tauri/Cargo.toml`,
`apps/desktop/src-tauri/tauri.conf.json`, `apps/desktop/package.json` и корневом
`package.json`. Рассинхрон валит CI (`scripts/check-versions.mjs`, M11.5):

```bash
node scripts/check-versions.mjs
```

## Подпись и разрешения macOS

Сборка подписывается ad-hoc (`bundle.macOS.signingIdentity = "-"`), нотаризации нет —
ограничение R6 паспорта.

Практическое следствие, о котором нужно помнить при каждом релизе: macOS привязывает выданные
разрешения к подписи приложения, а у ad-hoc-подписи нет стабильной идентичности. **После
обновления система с высокой вероятностью снова спросит Микрофон и Запись экрана.** Для
приложения, которому нужны оба, это заметная потеря — и снимается она только Apple Developer
Program.

Секреты нотаризации уже прописаны в `release-app.yml` закомментированными: при появлении
Developer ID достаточно раскомментировать их и завести значения.

## Аварийный откат релиза (M11.8)

В UI downgrade не выставлен. Для отката плохого релиза:

1. Опубликовать `vX.Y.Z+1` с кодом из последней рабочей версии — рекомендуемый путь.
2. Если форс-мажор: запустить клиент с `WOTOLD_UPDATER_ALLOW_DOWNGRADE=1` —
   `default_version_comparator` примет любую версию из манифеста, не равную текущей.

## Первый запуск на macOS

Сборка не нотаризована (R6 паспорта — сознательное ограничение MVP, не баг).
Gatekeeper при первом запуске потребует разрешения через **Системные Настройки →
Конфиденциальность и Безопасность → «Открыть всё равно»**.
